# AI Agents & Automation

This document describes automation tooling and AI agent integration for NextLaBIS, including GitHub Copilot Coding Agent configuration, GitHub Projects v2 setup, and the TODO-to-Issues synchronization system.

## Quick Reference

| Task              | Command / Action                            | Description                                           |
| ----------------- | ------------------------------------------- | ----------------------------------------------------- |
| **Scan TODOs**    | `npm run sync-todos`                        | Scan codebase, generate `todo-issues.json`            |
| **Enhance JSON**  | Ask Copilot: "Enhance the todo-issues.json" | AI agent adds detailed descriptions, criteria, labels |
| **Create Issues** | `npm run sync-todos:create`                 | Create GitHub issues from JSON, update code comments  |
| **Dry Run**       | `npm run sync-todos:dry-run`                | Preview changes without creating issues               |

## GitHub Copilot Coding Agent

The project includes a custom GitHub Copilot Coding Agent for enhancing TODO issue data.

### Agent Files

| File                                                                    | Purpose                                          |
| ----------------------------------------------------------------------- | ------------------------------------------------ |
| [AGENTS.md](../AGENTS.md)                                               | Main agent instructions (repository root)        |
| [.github/agents/todo-to-issues.md](../.github/agents/todo-to-issues.md) | Specialized TODO-to-Issues agent (JSON enhancer) |

### Workflow Overview

The TODO-to-Issues workflow uses a **three-step process** with JSON as an intermediary:

```
Step 1: npm run sync-todos
        ↓ Scans codebase, generates todo-issues.json

Step 2: Ask Copilot to enhance the JSON
        ↓ AI analyzes code context, writes detailed descriptions

Step 3: npm run sync-todos:create
        ↓ Creates GitHub issues, updates source files with issue numbers
```

**Why this approach?**

- No automatic PRs – you control when issues are created
- Human review before issue creation
- AI-enhanced issue descriptions with context
- Separation of concerns (scanning vs. analysis vs. creation)

### How to Use the Agent

1. **Generate the JSON file:**

   ```bash
   cd nextapp
   npm run sync-todos
   ```

2. **Ask Copilot to enhance it:**
   - Open the generated `nextapp/todo-issues.json`
   - Use one of these prompts:
     - "Enhance the todo-issues.json with detailed descriptions"
     - "Analyze the TODOs and write better issue descriptions"
     - "Fill in the TODO issue details"

3. **Review and create issues:**

   ```bash
   # Preview what will be created
   npm run sync-todos:dry-run

   # Create issues (requires GITHUB_TOKEN)
   npm run sync-todos:create
   ```

### What the Agent Does

When you ask Copilot to enhance the JSON, it:

1. **Reads** `nextapp/todo-issues.json` (generated by scan)
2. **Analyzes** surrounding code context for each TODO
3. **Writes** for each entry:
   - Detailed `description` explaining what needs to be done
   - `suggestedImplementation` with code patterns and approach
   - `acceptanceCriteria` as a checklist
   - `estimatedComplexity` (low, medium, high)
   - Appropriate `labels` based on file path and content
4. **Saves** the enhanced JSON (same file)

### What the Agent Does NOT Do

- ❌ Create pull requests
- ❌ Directly create GitHub issues
- ❌ Modify source code files
- ❌ Run scripts or terminal commands

### JSON Schema

The `todo-issues.json` file has this structure:

```json
{
  "generatedAt": "2025-01-15T10:30:00Z",
  "repository": "cckssr/NextLaBIS",
  "todos": [
    {
      "id": "todo_1",
      "type": "TODO",
      "comment": "Implement proper error handling",
      "file": "src/lib/spaces/getSpaceOverview.ts",
      "line": 42,
      "existingIssue": null,
      "title": "Implement proper error handling in getSpaceOverview",
      "description": "",
      "suggestedImplementation": "",
      "acceptanceCriteria": [],
      "labels": ["type:tech-debt", "source:code-comment"],
      "estimatedComplexity": "medium"
    }
  ]
}
```

The agent fills in `description`, `suggestedImplementation`, `acceptanceCriteria`, and refines `labels`.

## TODO-to-Issues Script

The script has two modes: **SCAN** and **CREATE**.

### SCAN Mode (Default)

Scans the codebase for `TODO`, `FIXME`, and `FEAT` comments and generates a JSON file:

```bash
cd nextapp
npm run sync-todos
```

This creates `nextapp/todo-issues.json` with all found comments.

### CREATE Mode

Reads the JSON file and creates GitHub issues:

```bash
cd nextapp
npm run sync-todos:create
```

This requires `GITHUB_TOKEN` environment variable.

### Comment Patterns

The agent recognizes these patterns:

```typescript
// TODO: Description of work to be done
// FIXME: Description of bug or issue to fix
// FEAT: Description of new feature to implement

// Multi-line (only first line gets issue number):
// TODO: This is a complex task
// that spans multiple lines
// but only the first line gets tagged

// JSX comments:
{
  /* TODO: Fix this component */
}

// Block comments:
/* TODO: Implement this function */
```

### After Processing

Comments are updated with issue numbers:

```typescript
// Before:
// TODO: Implement zod validation for OpenBIS types

// After:
// TODO(#42): Implement zod validation for OpenBIS types
```

### Duplicate Detection

The agent prevents duplicate issues by:

1. Searching existing issues with label `source:code-comment`
2. Matching the `Source Location` custom field (`file:line`)
3. Skipping creation if an issue already exists for that location

### Phase Detection

The agent auto-detects phase from comment content:

| Keyword in Comment | Label Applied             |
| ------------------ | ------------------------- |
| "Phase 0"          | `phase:0-foundations`     |
| "Phase 1"          | `phase:1-api-integration` |
| "Phase 2"          | `phase:2-eln-features`    |

### Feature Detection

The agent maps file paths to feature labels:

| Path Contains            | Label Applied         |
| ------------------------ | --------------------- |
| `components/dashboard/`  | `feature:dashboard`   |
| `components/spaces/`     | `feature:spaces`      |
| `components/objects/`    | `feature:object-view` |
| `components/masterdata/` | `feature:masterdata`  |
| `lib/model/`             | `feature:type-system` |

## GitHub Projects v2 Integration

### Prerequisites

1. Create a GitHub Project (Projects v2) in your repository
2. Create custom fields (see schema below)
3. Note the Project ID and Field IDs
4. Set up authentication (see Authentication section)

### Custom Fields Schema

Create these custom fields in your GitHub Project:

| Field Name      | Type          | Options                             | Purpose                                      |
| --------------- | ------------- | ----------------------------------- | -------------------------------------------- |
| Source Type     | Single Select | `TODO`, `FIXME`, `FEAT`             | Categorize code comment type                 |
| Source Location | Text          | -                                   | File path and line number (`src/file.ts:42`) |
| Auto-Generated  | Checkbox      | -                                   | Mark issues created by automation            |
| Phase           | Single Select | `Phase 0`, `Phase 1`, `Phase 2`     | Development phase alignment                  |
| Priority        | Single Select | `Low`, `Medium`, `High`, `Critical` | Issue priority                               |

### Getting Project and Field IDs

Run this GraphQL query in [GitHub GraphQL Explorer](https://docs.github.com/en/graphql/overview/explorer):

```graphql
query GetProjectInfo {
  repository(owner: "cckssr", name: "NextLaBIS") {
    projectsV2(first: 10) {
      nodes {
        id
        title
        fields(first: 20) {
          nodes {
            ... on ProjectV2SingleSelectField {
              id
              name
              options {
                id
                name
              }
            }
            ... on ProjectV2Field {
              id
              name
            }
          }
        }
      }
    }
  }
}
```

### GraphQL Mutations Reference

**Add Issue to Project:**

```graphql
mutation AddToProject($projectId: ID!, $contentId: ID!) {
  addProjectV2ItemById(
    input: { projectId: $projectId, contentId: $contentId }
  ) {
    item {
      id
    }
  }
}
```

**Update Single Select Field:**

```graphql
mutation UpdateField(
  $projectId: ID!
  $itemId: ID!
  $fieldId: ID!
  $optionId: String!
) {
  updateProjectV2ItemFieldValue(
    input: {
      projectId: $projectId
      itemId: $itemId
      fieldId: $fieldId
      value: { singleSelectOptionId: $optionId }
    }
  ) {
    projectV2Item {
      id
    }
  }
}
```

**Update Text Field:**

```graphql
mutation UpdateTextField(
  $projectId: ID!
  $itemId: ID!
  $fieldId: ID!
  $text: String!
) {
  updateProjectV2ItemFieldValue(
    input: {
      projectId: $projectId
      itemId: $itemId
      fieldId: $fieldId
      value: { text: $text }
    }
  ) {
    projectV2Item {
      id
    }
  }
}
```

## Authentication

### Local Development

Create a `.env.local` file in `nextapp/` (gitignored):

```bash
# GitHub Personal Access Token
# Required scopes: repo, project, read:org
GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx

# Optional: GitHub Project ID (from GraphQL query above)
GITHUB_PROJECT_ID=PVT_xxxxxxxxxxxx
```

### GitHub Actions

Add secrets in repository settings:

1. Go to **Settings** → **Secrets and variables** → **Actions**
2. Add `GH_PAT` with a Personal Access Token (scopes: `repo`, `project`, `read:org`)
3. Add `GITHUB_PROJECT_ID` with your Project ID

> **Note:** The default `GITHUB_TOKEN` does not have project permissions. Use a PAT.

### Token Scopes Required

| Scope      | Purpose                                    |
| ---------- | ------------------------------------------ |
| `repo`     | Read/write issues, read code               |
| `project`  | Read/write GitHub Projects v2              |
| `read:org` | Read organization projects (if applicable) |

## Troubleshooting

### "Bad credentials" error

- Verify your `GITHUB_TOKEN` is set correctly
- Check token hasn't expired
- Ensure token has required scopes

### "Project not found" error

- Verify `GITHUB_PROJECT_ID` is correct
- Ensure token has `project` scope
- Check project is accessible to the token owner

### Issues not appearing in Project

- GraphQL mutations may fail silently
- Check the script output for errors
- Verify field IDs are correct

### Duplicate issues created

- The `source:code-comment` label must exist
- Check the `Source Location` field is being set correctly
- Verify the duplicate detection query
